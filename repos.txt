# Corpus sources for `sm-eval mine` (SPEC §6.1, milestone M1).
#
# Format: <clone-url> <SPDX licence>   — `#` starts a comment, blank lines are
# ignored, and the licence column is optional (it defaults to UNKNOWN).
#
# ## Selection
#
# The methodology follows the prior work we intend to be comparable with —
# Spork's `replication/candidate_projects.txt` and jdime's ASE'15 study; see
# docs/prior-art.md §4. Criteria:
#
#   * Java is the primary language, so `.java` conflicts are the norm rather
#     than an accident of a polyglot repository.
#   * Long-lived, so `git log --merges` has thousands of two-parent merges.
#   * Actively maintained, so the corpus reflects how Java is written now.
#   * Diverse in domain and house style — Apache server-side, Google and Square
#     libraries, IDE and compiler infrastructure, test frameworks,
#     static-analysis tools — so no single project's conventions dominate.
#
# ## Ordering
#
# Sorted by the number of two-parent merge commits reachable from the default
# branch, measured with blobless clones before this list was written. That is
# deliberate: the miner processes one repository at a time and writes the
# manifest after each, so a run that is stopped early has still visited the
# repositories that carry the corpus.
#
# The counts in the right-hand comment are what that survey found. They are a
# *ceiling*, not a yield: most of these merges turn out to be fast-forwards
# recorded with `--no-ff`, where the merge base is one of the parents and there
# is no three-way decision to learn from. `docs/corpus-summary.md` has the real
# numbers.
#
# ## Note on merge counts
#
# Several well-known Java projects appear here with almost no merges. That is
# not an error and they are kept on purpose: `apache/kafka` (42),
# `apache/hbase` (19), `apache/pulsar` (7), `apache/zookeeper` (3),
# `google/guava` (1) and `apache/iceberg` (0) squash or rebase their pull
# requests, so their default branches are nearly linear and carry no
# three-way merge history at all. Their rows in the summary are a finding about
# where mineable merge history actually lives, and dropping them would quietly
# bias the picture.
#
# ## Note on licences
#
# The corpus is gitignored and never redistributed; the licence column exists
# so `sm-eval sample` can restrict the small *committed* fixture set to
# permissively licensed sources. Non-permissive entries are therefore fine to
# mine and are simply never sampled. `elastic/elasticsearch` is the notable
# one: it was Apache-2.0 through 7.10 and is now tri-licensed under AGPL-3.0,
# ELv2 and SSPL.
